# 提交进度条 + 内外网切换 实施计划

## 需求归纳

1. 提交时显示旋转进度条对话框，提交完毕（成功/失败）自动关闭。
2. 重启 App（进程重启）默认以内网方式提交。
3. 外网提交不通 → 立即切换为内网优先，并关闭轮询定时。
4. 内网提交不通 → 自动切换为外网优先，后续提交不再立即回试内网；
   启动定时轮询（默认 30 分钟一次，间隔可在 conf.json 配置），
   后台线程 ping 内网 IP：ping 通 → 切回内网优先并关闭定时；ping 不通 → 继续等待下一轮；
   退出 App（Activity 销毁）前必须关闭定时。

## 状态模型

运行时单点状态 `InvoiceApi.preferInternal`（static volatile boolean，默认 true）：

- 进程启动即为 true → 天然满足"重启 App 默认内网"；
- 提交顺序 = 先 `preferInternal` 对应网络，连接层异常再试另一网络；
- 切换规则（仅在**连接层失败**时触发；HTTP 409/401 等服务器有响应的结果不触发切换）；
  **只有对侧网络实际提交成功才切换，两侧均失败则保持原优先方向不变**：
  | 场景 | 动作 |
  |---|---|
  | 内网优先：内网连接失败、外网成功 | `preferInternal=false`，启动 ping 定时 |
  | 内网优先：内外网连接均失败 | 不切换（保持内网优先），不启动定时，报"均连接失败" |
  | 外网优先：外网连接失败、内网成功 | `preferInternal=true`，关闭 ping 定时 |
  | 外网优先：内外网连接均失败 | 不切换（保持外网优先），定时继续运行，报"均连接失败" |
  | 优先网络提交成功（任意方向） | 不切换；若当前为外网优先则定时继续运行 |

## 一、新增文件

### 1. `utils/InternalPingMonitor.java` — 内网轮询监控
- 静态工具类，内部 `ScheduledExecutorService`（单线程、daemon）。
- `start(intervalMinutes)`：幂等——已启动则忽略；周期执行 ping。
- `stop()`：取消定时并置空（幂等），退出 App 时调用。
- `isRunning()`：便于日志与测试。
- ping 实现：`String[] cmd = {"/system/bin/ping", "-c", "1", "-W", "3", "<internalIp>"};Runtime.exec(cmd)`，exit==0 视为通
  （Android 上 `InetAddress.isReachable` 对 ICMP 不可靠，用系统 ping 命令）。
- ping 通：`InvoiceApi.setPreferInternal(true)` + `stop()`，日志"内网恢复，切回内网提交"；
  不通：日志记录，等待下一轮。
- 间隔取自 `AppConfig.getPingIntervalMinutes()`（每次 start 时读取）。

### 2. `res/layout/dialog_progress.xml` — 提交进度对话框
- 横向 LinearLayout：`ProgressBar`（spinner 旋转样式，28dp）+ TextView「提交中…」，
  白底圆角、居中，宽 wrap_content。

## 二、修改文件

### 1. `utils/AppConfig.java`
- 新增字段 `pingIntervalMinutes`，key=`pingIntervalMinutes`，默认 `30`
  （常量 `DEFAULT_PING_INTERVAL_MINUTES`），load/save/getter/setter 补齐。
- `restoreDefaults()` 同时恢复该项为 30。
- 该值仅通过修改 conf.json 文件配置，不进设置菜单（按需求）。

### 2. `utils/InvoiceApi.java`
- 新增 `preferInternal` 状态与 `isPreferInternal()/setPreferInternal(boolean)`。
- `submit()` 改为按优先顺序尝试：`first = preferInternal ? internal : external`，
  连接层异常（postTo 返回 null）再试 second；
  按上表更新 `preferInternal` 并调用 `InternalPingMonitor.start/stop`；
  日志打印本次实际使用的网络与切换决策。
- 服务器有响应（200/409/其他状态码）→ 不触发切换、不动定时。

### 3. `MainActivity.java`
- `submitInvoice()`：
  - 提交前用 `dialog_progress.xml` 构建 AlertDialog（`setCancelable(false)`），
    保存为成员 `submitProgressDialog`；
  - 子线程结果回主线程后先 `dismiss` 进度框，再走现有 SUCCESS Toast / 409/错误对话框 /
    连续扫描逻辑（均不变）；
  - 防止重复弹出：弹出前若已 showing 则复用。
- `onDestroy()`：`InternalPingMonitor.stop()`（退出 App 关闭定时）。
- 无需在 onCreate 重置优先网络（进程重启 static 即为内网优先）。

## 三、验证

- `gradlew :invoice:assembleDebug` 编译通过；
- 场景自测（可用日志关键字核对）：
  1. 提交时进度框出现、结束自动消失，期间无法操作/取消；
  2. 拔内网 → 提交走外网成功 → 日志显示切换外网+定时启动；再次提交仍先走外网；
  3. 恢复内网 → 下一轮 ping 通 → 切回内网、定时关闭；
  4. 外网优先时外网断、内网通 → 立即切回内网并关定时；内外网全断 → 保持外网优先、定时继续，
     内网恢复后由 ping 切回；
  5. 内网优先时内外网全断 → 保持内网优先、不启动定时，报"均连接失败"；
  6. 杀进程重进 → 默认内网优先；
  7. conf.json 改 `pingIntervalMinutes` 后重启生效；恢复默认值后回到 30。
